# Ultra-Fusion ROS1 Noetic v0.1.2

This release improves ROS1 Noetic runtime stability and performance and adds
opt-in LiDAR map PCD export.

## Highlights

- Adds flag-gated map recording. It is disabled in every shipped profile.
  When enabled, the first LiDAR world cloud is saved and a new keyframe is
  written after either the configured translation or rotation threshold is
  reached. A ROS Trigger service merges those keyframes into `map.pcd`.
- Reduces LVWIO memory and copy overhead by moving LiDAR buffers, releasing
  retained visual frames, and compacting sampled-cloud capacity.
- Hardens RGB-D depth-only initialization and rejects invalid depth or
  optimized inverse-depth values.
- Makes visual outlier refinement transactional so a rejected refinement does
  not partially mutate estimator state or the marginalization prior.
- Improves GNSS input/configuration validation and fixes the optimized ECEF
  anchor Jacobian.
- Hardens ROS1 multi-camera synchronization, explicit
  `camera_id`-to-extrinsic selection, buffer ownership, bag drain, and clean
  shutdown behavior.
- Adds estimator-policy and regression coverage for sensor readiness, LiDAR
  quality, ZUPT behavior, marginalization lifetime, and memory contracts.

## Map PCD configuration

The released default remains safe and side-effect free:

```yaml
map_pcd:
  enable: false
  output_directory: "/tmp/Ultrafusion"
  translation_threshold_m: 2.0
  rotation_threshold_deg: 30.0
  service_name: "/ultrafusion/generate_map_pcd"
```

With `enable: true`, keyframes are written under
`<output_directory>/keyframes/`. Generate the combined map before stopping the
node:

```bash
rosservice call /ultrafusion/generate_map_pcd
```

The result is `<output_directory>/map.pcd`. No directory, keyframe, or service
is created while the flag is false.
